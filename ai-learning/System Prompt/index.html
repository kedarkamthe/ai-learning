System Prompts

Designing how AI thinks — before it ever answers you.

15 MIN · FOR AI BEGINNERS · KK · RED HAT
The Problem

Same question. Two very different answers.

No system prompt
"Review this code."

→ "Looks fine! Consider adding comments and maybe some tests."
With a system prompt
"Review this code."

→ "CRITICAL: No timeout on line 14 — requests will hang under load. Here's the fix: ..."

The AI didn't change. The instructions did. That's what a system prompt is for.

Component 1 of 5

ROLE — Who is answering?

You're not giving instructions. You're choosing an identity — a way of thinking, shaped by real experience.

Too vague
"You are a software engineer. Be a good reviewer."
Specific
"You are a Senior Backend Engineer with 10 years optimizing Go microservices at scale."
Component 2 of 5

CONSTRAINT — What should it focus on?

Say what to focus on — and what to ignore. Every constraint narrows a thousand possible answers down to the one you need.

Too broad
"Be thorough, concise, and cover everything important."
Narrowed
Focus: security & data exposure.
Ignore: code style, comments.
Component 3 of 5

REASONING — In what order should it think?

The same code. The same reviewer. A different order — a completely different review.

Readability first
"Consider clearer variable names... also, watch for a possible SQL injection."
Security first
"CRITICAL: SQL injection on line 8. Fix this before anything else."

What you evaluate first shapes everything that follows.

Component 4 of 5

FORMAT — How should the answer look?

Structure turns an answer into something you can actually use. Show an example — don't just describe it.

**[Issue Title]** Severity: Critical / High / Medium Diagnosis: what's wrong Impact: why it matters Fix: exact change
Component 5 of 5

CALIBRATION — When should it say "I'm not sure"?

Confidence should reflect what the model actually understands — not just how certain it sounds.

Hollow confidence
"Use Kafka. It's the best choice."
Honest confidence
"I'm 55% confident — I understand Kafka's strengths, but not your latency budget."
Validate Before You Trust It
