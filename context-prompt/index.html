AI FUNDAMENTALS · SESSION 01

How Your AI Agent
Actually Thinks

Understanding the context prompt — the structure behind every AI agent — explained technically, then through something you already understand: a trip to the doctor.

15 MIN·BEGINNER FRIENDLY·NO CODE REQUIRED
DEFINITION

What exactly is a "context prompt"?

A context prompt is the complete, structured input an AI agent receives on every single call. Not just your question — five distinct sections, bundled together, every time:

system — the rules tools — the abilities memory — the history user_message — the ask assistant — the response

We'll go through each of these five pieces one at a time — what it technically does, and a simple analogy to make it stick.

WHY IT EXISTS

Why does this structure exist at all?

A language model call is stateless by default. On its own, it has none of these three things:

Missing #1

No memory between calls

Missing #2

No fixed role or rules

Missing #3

No way to act on the world

The context prompt is the engineering pattern that supplies all three — every single call, from scratch. Get any one section wrong, and the agent looks perfect in a demo, then breaks the moment it's asked to do something multi-step.

THE LENS

To make these five pieces stick, we'll use one analogy for the rest of this talk: a visit to the doctor.

Every doctor visit has the same five ingredients, always in the same order. Once you can map the two side by side, the whole architecture clicks — permanently.

PIECE 1 OF 5 · RULES

<system> — the rules that never change

Technical Definition

Fixed instructions given to the agent before anything else. They define its role, tone, and hard boundaries — and stay identical throughout the entire conversation.

The Analogy

A doctor's medical license and oath. The same standards apply to every patient, every visit — they don't get rewritten each morning.

<system> You are a support assistant. Never share a customer's personal data. Always ask before taking an action that can't be undone. </system>
PIECE 2 OF 5 · ABILITIES

<tools> — what the agent is allowed to use

Technical Definition

A list of functions the agent is allowed to call — search the web, check a database, send an email — to fetch information or take action in the real world.

The Analogy

The equipment sitting in a clinic — the ECG machine, the blood lab, the X-ray. Always available, ready the moment the doctor needs them.

<tools> search_web(query) check_order_status(order_id) send_email(to, subject, body) </tools>
PIECE 3 OF 5 · WHAT STAYS

<memory> — the patient file

Technical Definition

Facts and results carried over from earlier steps. It grows over time — but it only ever stores outcomes, never the reasoning that produced them.

The Analogy

The doctor doesn't recall every thought from your last visit — but your file always shows the diagnosis, the test results, and the medication.

<memory> Diagnosis: Mild asthma Last visit: Prescribed inhaler Follow-up: Check in after 30 days </memory>
PIECE 4 & 5 OF 5 · THIS MOMENT

<user_message> + <assistant> — today's visit

<user_message>

Technical Definition

The current request. Fresh every single time, with no memory of its own.

The Analogy

What you tell the doctor today — "I still have a cough."

<assistant>

Technical Definition

The agent's reasoning and actions for this one turn only. It is generated fresh and never carried into the next request.

The Analogy

The doctor's thinking, right now — examining you, reasoning, deciding. The moment the visit ends, this thinking is gone.

THE INSIGHT

"The reasoning is regenerated every time.
Only the outcomes are ever saved."

Exactly like a doctor — they don't recall their exact train of thought from your last visit. They read the file, and think fresh. This is why agents seem to "lose the plot": teams expect them to remember reasoning that was never meant to persist.

THE FULL PICTURE

One request, three moments

01
Visit begins

Rules (system), abilities (tools), and the file (memory) are all read, along with today's request.

→
02
Doctor reasons

The agent thinks, decides, acts — this is assistant. It's shown to you, then discarded completely.

→
03
File gets updated

Only the outcome is written back into memory — ready for the next visit.

Every AI agent, no matter how advanced, is running this same loop underneath.

TAKEAWAY

"Next time you build — or just use — an AI agent, ask yourself: what belongs in memory, and what's just today's thinking?"
